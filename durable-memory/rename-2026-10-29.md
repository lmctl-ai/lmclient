# Rename lmdb to lmclient (2026-10-29)

Version 0.2.0 renames the project from `lmdb` to `lmclient`. The GitHub
repository is `lmctl-ai/lmclient`; the old URLs redirect. The JDBC
functionality and the five bundled drivers are unchanged.

## What changed

- Binary and CLI name `lmclient`; `--version` prints `lmclient 0.2.0`;
  stderr messages are prefixed `lmclient: `.
- Java package `ai.lmctl.lmdb` is `ai.lmctl.lmclient`; the Maven
  artifactId, main class, native image name and shaded jar
  (`lmclient-0.2.0-all.jar`) follow. Native-image config directories are
  `META-INF/native-image/ai.lmctl/lmclient{,-h2,-duckdb}`, and the
  generator scripts write there.
- DSL identity: the HostApi schema reports `"name":"lmclient"` and every
  example binds `_dsl_ cli="lmclient" install="github:lmctl-ai/lmclient@latest"`.
  The `dsl.schema` protocol version stays 2; the host contract did not change.
- Environment variables are `LMCLIENT_*` (`LMCLIENT_URL`,
  `LMCLIENT_USER`, `LMCLIENT_PASSWORD`, `LMCLIENT_CREDENTIALS_FILE`,
  `LMCLIENT_MAX_MEMORY_MB`, the internal `LMCLIENT_INTERNAL_HEAP_BYTES`, and
  the build-time `LMCLIENT_STATIC_LIBDIR`).
- CI artifacts and release assets are `lmclient-<os>-<arch>`; the CI
  service credentials were renamed as well.
- The gallery image `docs/images/lmclient_schema_map.png` replaces
  `lmdb_schema_map.png`.

## Back-compat: the `LMDB_*` alias

The Java code reads environment variables through `ai.lmctl.lmclient.core.Env.get`,
which returns the `LMCLIENT_*` value and, when that is unset, the matching
`LMDB_*` value. Scripts that exported `LMDB_URL` or `LMDB_PASSWORD` for
0.1.x therefore keep working against the 0.2.0 binary. Our own scripts and
CI use the new names only; the alias is for users. It is a fallback, never
a merge: a set `LMCLIENT_*` name wins even when the `LMDB_*` one is also set.

## Why a major-feeling bump at 0.2.0

The CLI name and the DSL identity are the public contract: an lmscript
program binding `cli="lmdb"` will not find the new binary, and release
assets have new names. That is a breaking change under 0.x semantics, so
the minor version moved. Earlier chapters in this memory keep the `lmdb`
name because they record what was true when written.
